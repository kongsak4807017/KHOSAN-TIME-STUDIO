## 197 — Data Privacy และ Telemetry Policy ครอบคลุมอะไร?

**1. Direct Answer:** เอกสาร Weave ยืนยันว่ามี Player Identity, Local/Hosted Persistence, In-game Chat และบางส่วนของ Viewer-local UI State แต่ **ยังไม่มีข้อมูลเพียงพอที่จะรับรอง Privacy Policy ฉบับเต็ม** เช่นประเภท Telemetry ที่จัดเก็บจริง ระยะเวลาเก็บข้อมูล การส่งข้อมูลให้ Third Parties หรือกระบวนการลบข้อมูลผู้ใช้

**2. Architecture:** คู่มือแยก Shared Simulation State จาก Viewer-local Presentation และ Hosted Save Storage โดยระบบ Multiplayer จำลอง Shared State บน Clients ที่เข้าร่วม ไม่ใช่ Secret Server-only State

**3. Source Evidence:** `multiplayer_guidance`, `persistent_state_v1`, `html_ui → World chat`

**4. API Contract และ Data Boundaries:**

| ข้อมูล | Behavior ที่คู่มือระบุ |
|---|---|
| Player gameplay fields | Shared Deterministic Simulation |
| Viewer-local UI focus/dialog | ไม่ใช่ Shared Gameplay State |
| Player-owned Canvas | จำกัดการแสดง/Hit-testing ตาม Viewer |
| Hosted player saves | ผูกกับ Oriverse Account |
| World Chat | Viewer-local Chat Bindings แยกจาก Weave Simulation/AI Context |
| Chat UI inspection | Redact Chat Content ใน Inspection/Preview |
| Telemetry retention | Undisclosed |

**5. Working Example — การออกแบบ Privacy Boundary สำหรับ KHOSAN:**

```json
{
  "data_class": "player_chat",
  "visibility": "authorized_chat_participants",
  "gameplay_state": false,
  "ai_context_access": false,
  "retention_days": null,
  "policy_status": "requires_official_confirmation"
}
```

เป็น Proposed Data Classification ไม่ใช่ Oriverse Privacy API

**6. Execution Trace — Expected จากคู่มือ:** Player Joins → Identity-based State Restored → Shared Simulation Runs → Viewer-local Chat/UI Handles Local Interaction → Hosted Saves Sync in Background

**7. Limits & Failure Modes:** การซ่อน UI ไม่ทำให้ข้อมูลใน Shared Simulation เป็นความลับ และการใช้ชื่อผู้เล่นเป็น Unique Identifier ไม่ปลอดภัย เพราะ `GetPlayerName()` ไม่รับรองความไม่ซ้ำ

**8. Verification:** Expected: Chat Binding ไม่เปิดเผยเนื้อหาใน UI Inspection และ Gameplay State ไม่ถูกเข้าใจผิดว่าเป็น Private; Actual: Documented แต่ยังไม่ได้ทดสอบ Privacy Leakage หรือ Data Subject Requests

**9. Disclosure Status:** Selected Data Boundaries `Documented`; Privacy/Telemetry Policy, Retention และ Third-party Transfers `Undisclosed`

**10. Research Gaps:** Privacy Notice, Consent, Data Retention, Encryption, Data Export/Deletion, Incident Reporting, Cross-border Processing และ PDPA/GDPR Applicability

## 198 — Team Collaboration และ Audit Logs

**1. Direct Answer:** Oriverse รองรับ Project Ownership, Editor Sessions, Revision/Snapshot Validation และการบันทึกชื่อ Summary ของ Submission แต่ยังไม่พบ Public API ที่ยืนยันระบบ Team Roles, Branch Protection, Multi-user Approval, Audit Log Export หรือการติดตามการเปลี่ยนแปลงโดยผู้ร่วมงานแต่ละคนอย่างครบถ้วน

**2. Architecture:** เครื่องมือที่เปิดเผยรองรับ Agent-to-Editor Routing, Draft Validation และ Submission History Metadata บางประเภท ส่วน Collaboration Governance สำหรับหลายผู้ใช้ต้องแยกจาก Session Routing

**3. Source Evidence:** `list_editors`, `select_editor`, `patch_and_run_pending_world`, `submit_pending_world`, `request_project_save`

**4. API Contract:** `patch_and_run_pending_world` รับ `expected_revision` สำหรับกัน Stale Updates และ `submit_pending_world` รับ `summary` เพื่อระบุการเปลี่ยนแปลง ส่วน Editor Selection ใช้ `editor_id` และ `agent`

**5. Working Example — Proposed Audit Event:**

```json
{
  "event": "world_patch_requested",
  "actor": "agent-or-user",
  "project": "example-project",
  "expected_revision": 12,
  "result_revision": null,
  "approval_required": true,
  "tool_result": "not_executed"
}
```

นี่เป็น KHOSAN Audit Schema ไม่ใช่ Log Format ของ Oriverse

**6. Execution Trace — Expected:** Agent Selects Editor → Reads Revision → Proposes Patch → Revision Validated → Compilation Runs → Submission Creates History Summary → User Loads

**7. Limits & Failure Modes:** Revision Guard ป้องกัน Stale Edits ได้บางกรณี แต่ไม่ใช่ระบบ Permission Approval หรือ Audit Integrity โดยอัตโนมัติ และ Submission Summary ไม่ใช่ Complete Immutable Audit Log

**8. Verification:** Expected: สามารถตรวจเส้นทาง Edit/Submit และจับ Stale Revision ได้; Actual: ตรวจ Tool Contract และพบ Editor Session จริง แต่ไม่ได้รัน Concurrent Editing หรือ Audit Export

**9. Disclosure Status:** Editor/Draft Metadata `Documented`; Team RBAC/Audit Log System `Undisclosed`

**10. Research Gaps:** Team Roles, Invitation, Review Workflow, Immutable History, Branching/Merging, Signature-based Approval และ SOC 2/ISO 27001 Evidence

## 199 — Licensing, Monetization และ Commercial-use Restrictions

**1. Direct Answer:** ยังไม่พบหลักฐานเพียงพอจากคู่มือ/API ที่ตรวจให้สรุปสิทธิ์เชิงพาณิชย์ของ Weave Code, Generated Assets, Marketplace Library Assets หรือ Hosted Runtime อย่างครอบคลุม

เช่นเดียวกัน ไม่พบ Public Contract ที่ระบุระบบ In-app Purchases, Revenue Share, Royalties, Subscription Billing หรือ Marketplace Payouts สำหรับเกมที่สร้างขึ้น

ดังนั้นต้องตอบว่า **Commercial Rights / Licensing Terms: Not Verified** และ **Monetization Framework: Undisclosed**

**2. Architecture:** สิทธิ์ใช้งานต้องพิจารณาแยกตาม Source Code, Procedural Assets, Third-party/Marketplace Assets, Hosted Publishing และ External-engine Export เพราะแต่ละส่วนอาจอยู่ภายใต้ข้อกำหนดต่างกัน

**3. Source Evidence:** `asset_aliases`, `save_mesh_asset`, `save_material_asset`, `save_clip_asset`, `share_game`, `publish_game`, `generate_image`

**4. API Contract:** เครื่องมือมี Contracts สำหรับการสร้าง เก็บ และเผยแพร่ Assets/Games แต่ไม่มี Verified Fields สำหรับ `license_id`, `royalty_rate`, `commercial_use_allowed`, `payment_provider` หรือ `revenue_share`

**5. Working Example — Proposed Release Compliance Manifest:**

```json
{
  "product": "KHOSAN Game",
  "weave_source_rights": "unverified",
  "generated_assets_rights": "unverified",
  "marketplace_assets_rights": "unverified",
  "external_distribution": "blocked_pending_review",
  "commercial_release": "blocked_pending_review",
  "required_evidence": [
    "official_terms",
    "asset_license",
    "distribution_rights"
  ]
}
```

เป็นข้อเสนอสำหรับ KHOSAN Studio ไม่ใช่ Oriverse License Contract

**6. Execution Trace — Proposed:** Assemble Release Manifest → Resolve Asset Licenses → Review Commercial Terms → Approve/Reject Distribution → Archive Rights Evidence

**7. Limits & Failure Modes:** การสร้าง Asset สำเร็จ ไม่ได้พิสูจน์กรรมสิทธิ์หรือสิทธิ์นำไปจำหน่าย และการสร้าง Public Playable URL ไม่ได้เท่ากับสิทธิ์นำ Runtime/Asset Binary ไปเผยแพร่บน Store อื่น

**8. Verification:** Expected: มีเอกสารสิทธิ์จากเจ้าของแพลตฟอร์มและผู้สร้าง Assets ยืนยันเงื่อนไขก่อนจำหน่าย; Actual: ไม่ได้ยืนยันเอกสาร Licensing/Monetization ฉบับปัจจุบันจากผู้ให้บริการ

**9. Disclosure Status:** Technical Publishing Capabilities `Documented`; Licensing/Monetization/Commercial Rights `Undisclosed / Not Verified`

**10. Research Gaps:** Terms of Service, IP Ownership, Asset Redistribution, Commercial Use, Revenue Share, Marketplace Payments, Tax Handling และ License Termination
