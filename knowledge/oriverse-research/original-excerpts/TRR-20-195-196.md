## 195 — Game Publishing และ Share Links มี Lifecycle อย่างไร?

**1. Direct Answer:** Oriverse มีเส้นทางเผยแพร่หลักสามแบบ ได้แก่ `submit_pending_world` เพื่อเสนอให้ Editor โหลด, `share_game` เพื่อสร้างลิงก์เล่นร่วมกันชั่วคราว และ `publish_game` เพื่อสร้างหรืออัปเดต Public Playable Project

ทั้งสามแบบมีผลแตกต่างกัน โดยเฉพาะ **Submit ไม่เท่ากับ Publish** และ Share Link ไม่เท่ากับ Permanent Project URL

**2. Architecture:** World Source → Compilation/Playtest → เลือก Delivery Channel → ตรวจสิทธิ์หรือ Source Validation ตาม Contract → ส่งผลถึง Editor หรือ Hosted Service

**3. Source Evidence:** Tool Contracts ของ `submit_pending_world`, `share_game`, `publish_game`, `get_load_status`

**4. API Contract:**

| Operation | Required Input | Output / Lifecycle |
|---|---|---|
| `submit_pending_world` | `summary`, `agent` | เสนอ Snapshot ให้ Editor กด Load |
| `share_game` | `agent`, optional `title` | Public Play Link อายุประมาณ 30 วัน |
| `publish_game` | `project_name`, `world_text`, optional `display_name` | Permanent Project Page URL |
| `get_load_status` | `agent`, optional `request_id` | ตรวจ Pending/Completed/Failed/Awaiting Click |

`share_game` ต้องมี Successful Playtest ของ Exact Current Staged Source และการเรียกแต่ละครั้งสร้าง Share Link ใหม่

`publish_game` หากพบ Project Name ที่ตรงกันในบัญชีผู้เรียก จะอัปเดตไฟล์เกมของ Project นั้น

**5. Working Example — ตัวอย่างการเรียก Publishing API:**

```javascript
await tools.mcp__Oriverse__share_game({
  title: "Village Test",
  agent: "<existing-agent-uuid>"
});
```

เป็นตัวอย่างตาม Tool Contract ยังไม่ได้เรียกจริง เพราะจะสร้าง Public Link ใหม่

**6. Execution Trace — Expected:** Validate Staged Source → Successful Playtest → Call `share_game` → Receive Link → ผู้เล่นเปิดเกม → Link หมดอายุในเวลาประมาณ 30 วัน

**7. Limits & Failure Modes:** การ Submit สำเร็จไม่ได้หมายความว่า Editor โหลดเกมแล้ว การสร้าง Share Link ใหม่ไม่ได้ต่ออายุลิงก์เก่าโดยอัตโนมัติ และการเรียก `publish_game` กับ Project Name เดิมอาจเปลี่ยน Public Game ที่ให้บริการอยู่

**8. Verification:** Expected: แต่ละ Delivery Channel คืนสถานะตาม Contract; Actual: `Documented` แต่ไม่ได้ Submit, Share หรือ Publish ในรอบนี้

**9. Disclosure Status:** Publishing Lifecycle `Documented`; Hosting Infrastructure / Deployment Rollback Internals `Undisclosed`

**10. Research Gaps:** Deployment Version History, Content Delivery Cache, Session Migration, Zero-downtime Publish, Rollback API และ Share-link Revocation

## 196 — Version Rollback, Backup และ Recovery

**1. Direct Answer:** Oriverse รองรับการกู้คืน World Source หลายแหล่งผ่านเครื่องมือ Editor เช่น Live, Failed Submission, Persisted Draft และ Last Successfully Loaded World รวมถึงรองรับ Named Game Saves และ Cloud Save Conflict Resolution ในเกมที่เผยแพร่

แต่ **ยังไม่พบข้อรับรองว่า Project Source มี Full Version-control History, Automatic Backups หรือ Point-in-time Recovery ตามระยะเวลาที่กำหนด**

**2. Architecture:** ต้องแยก Recovery สองชั้น คือ *Project/World Source Recovery* กับ *Player Gameplay Save Recovery* เพราะเป็นข้อมูลคนละประเภท

**3. Source Evidence:** `sync_pending_world_from_current`, `submit_pending_world`, `persistent_state_v1`, `example_html_game_saves`

**4. API Contract:**

```typescript
sync_pending_world_from_current({
  source: "live" | "failed" | "draft" | "lastworld",
  preview?: boolean,
  confirm_discard?: boolean,
  agent: string
})
```

สำหรับ Personal Saves มี `RequestCreateGameSave`, `RequestLoadGameSave`, `RequestOverwriteGameSave`, `RequestDeleteGameSave` และ `RequestResolveGameSave`

**5. Working Example — Read-only Recovery Inspection:**

```javascript
await tools.mcp__Oriverse__sync_pending_world_from_current({
  source: "lastworld",
  preview: true,
  agent: "<existing-agent-uuid>"
});
```

คำสั่ง `preview:true` ตรวจ Source โดยไม่แทนที่ Pending Draft

**6. Execution Trace — Expected:** World Load Failed → Inspect Failed/Lastworld Source → Compare Changes → Restore Appropriate Snapshot → Compile/Playtest → Submit Revised World

**7. Limits & Failure Modes:** การใช้ Recovery Source ผิดอาจทำให้การแก้ล่าสุดสูญหาย ส่วน `@persist` Migration มี Validation เช่นการลบหรือเปลี่ยนชนิด Fields อาจถูกปฏิเสธเพื่อป้องกัน Progress Damage

นอกจากนี้ Save Status `saved_on_device` ไม่ได้หมายถึงข้อมูล Sync ไป Cloud แล้ว

**8. Verification:** Expected: Recovery Preview ไม่แก้ Draft และสามารถระบุ Snapshot เพื่อกู้คืนได้; Actual: Tool Contract ยืนยัน แต่ยังไม่ได้ทดลองกู้คืน Failed Project หรือ Cloud Save Conflict ในรอบนี้

**9. Disclosure Status:** Recovery Sources / Game Saves `Documented`; Full Backup SLA / Project History `Undisclosed`

**10. Research Gaps:** Backup Frequency, Snapshot Retention, Disaster Recovery RPO/RTO, Cloud Sync Guarantees, Version Diff และ Production Rollback
